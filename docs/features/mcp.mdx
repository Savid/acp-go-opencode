---
title: MCP
description: Forward stdio and streamable HTTP MCP servers from an ACP session into OpenCode's native config.
---

Attach MCP servers to a session and the adapter registers them dynamically for
that session's canonical working directory, so OpenCode's own MCP client
connects to them. You
declare servers on the ACP lifecycle request (`WithSessionMCPServers`, or the
`mcpServers` field); the adapter translates and forwards them.

## Supported transports

| Transport | Accepted | Native entry |
|---|---|---|
| stdio | Yes | `"type": "local"` |
| streamable HTTP | Yes | `"type": "remote"` |
| SSE | No — rejected at lifecycle admission | — |
| ACP-transport | No — rejected at lifecycle admission | — |

A server with no transport is rejected with `no_transport` before its name is
checked. SSE and ACP transports are likewise rejected before name validation;
accepted stdio/HTTP entries then require a non-empty, unique name. The same
ordering applies to new, load, resume, and `_opencode/session/fork`.

## How forwarding works

Accepted servers are registered through authenticated `POST /mcp?directory=...`:

- **HTTP servers** become `"type": "remote"` entries carrying their `url` and
  any request `headers`.
- **stdio servers** become `"type": "local"` entries with a `command` array (the
  executable followed by its arguments) and an `environment` map. There is no
  separate `arguments` key — the command and its args are one array.

OpenCode caches each connected server's tool catalog. After a session lifecycle
request succeeds, the adapter disconnects and re-registers the exact
session-scoped MCP configuration immediately before that session's first native
prompt. This makes host-side grants armed between lifecycle completion and the
prompt visible to OpenCode instead of retaining the lifecycle-time catalog.

MCP state is removed when the session's directory scope closes and is never
written by the adapter into the shared config or portable store. Directory
ownership is released only after every native MCP deletion succeeds (a native
not-found response also proves absence). A failed deletion makes close fail
loudly, retains both the remaining registrations and directory principal, and
can be retried; another session cannot enter that directory while disconnection
is unproven. Because registration is directory-scoped, one canonical directory
admits only one live session principal; a second session or a different
credential fingerprint is rejected.

If initial scope setup fails and its partial registration cannot be disproved,
there is no live session handle through which cleanup could be retried. The
adapter therefore retains the principal and quarantines that shared runtime;
closing the Agent terminates the native process tree and supplies the final
disconnect proof.

<Note>
The adapter forwards MCP servers into OpenCode's native config; it does not
expose a public MCP transport route of its own.
</Note>

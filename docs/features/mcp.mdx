---
title: MCP
description: Forward stdio and streamable HTTP MCP servers from an ACP session into OpenCode's native config.
---

Attach MCP servers to a session and the adapter registers them dynamically for
that session's canonical working directory, so OpenCode's own MCP client
connects to them. You
declare servers on the ACP lifecycle request (`WithSessionMCPServers`, or the
`mcpServers` field); the adapter translates and forwards them.

## Supported transports

| Transport | Accepted | Native entry |
|---|---|---|
| stdio | Yes | `"type": "local"` |
| streamable HTTP | Yes | `"type": "remote"` |
| SSE | No — rejected at session start | — |
| ACP-transport | No — rejected at session start | — |

A server without a name is also rejected at session start.

## How forwarding works

Accepted servers are registered through authenticated `POST /mcp?directory=...`:

- **HTTP servers** become `"type": "remote"` entries carrying their `url` and
  any request `headers`.
- **stdio servers** become `"type": "local"` entries with a `command` array (the
  executable followed by its arguments) and an `environment` map. There is no
  separate `arguments` key — the command and its args are one array.

MCP state is removed when the session's directory scope closes and is never
written into the shared config or portable store. Because registration is
directory-scoped, one canonical directory admits only one live session
principal; a second session or a different credential fingerprint is rejected.

<Note>
The adapter forwards MCP servers into OpenCode's native config; it does not
expose a public MCP transport route of its own.
</Note>

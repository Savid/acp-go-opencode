---
title: Permissions
description: Set a session's default permission policy and bridge OpenCode's runtime permission prompts to ACP.
---

Permissions work at two levels: a static per-session policy that OpenCode
applies, and runtime prompts OpenCode raises for individual actions that the
adapter forwards to the ACP client.

## Session permission policy

Set a session's default policy with `_meta.opencode.options.permission` at
session start (or `WithOpenCodePermission` on an `OpenCodeOptions`). The adapter
passes the rule list in the native session-creation request. Policy never enters
the shared process config.

| Value | Effect |
|---|---|
| `ask` | OpenCode prompts for each guarded action (the default; an empty value is treated as `ask`). |
| `allow` | OpenCode proceeds without prompting. |
| `deny` | OpenCode denies guarded actions without prompting. |

Any other value is rejected with the uniform unsupported-field error.

## Runtime permission prompts

When the policy is `ask`, OpenCode emits native permission events
(`permission.v2.asked` / `permission.asked`) during a turn. The adapter maps
each to an ACP `session/request_permission` request only after the native tool
call has been published to ACP in the current turn. The request carries the
same ACP session id and tool-call id plus native metadata. Permission routing
is structural: the host accepts it only while that tool-call id is pending in
the addressed session's current turn epoch. It offers three options:

| Option id | ACP kind | Meaning |
|---|---|---|
| `once` | Allow once | Permit this action only. |
| `always` | Always allow | Permit and remember. |
| `reject` | Reject | Deny the action. |

The client's selection is relayed back to OpenCode. If the client cancels or the
request otherwise fails, the adapter replies `reject` to the native prompt.

<Warning>
The permission flow is load-bearing for user trust: the adapter never silently
auto-approves a runtime prompt. On cancellation, every pending native permission
request is rejected with a cancelled explanation and the prompt returns
`cancelled`.
</Warning>

title: Install
description: Install the adapter as a library or a CLI binary, and the native OpenCode it wraps.
---

`acp-go-opencode` ships as both an importable Go package and a command binary.
Which you install depends on whether you embed the adapter or run it as a
subprocess.

## Requirements

- Go matching the module's `go` directive in `go.mod`.
- OpenCode `1.18.3` or newer with `serve` and the online sync-event schema.
- Provider credentials configured in OpenCode for any live prompt.

## Install the library

To embed the adapter in your own host through `opencodeacp.Serve`:

```sh
go get github.com/savid/acp-go-opencode
```

## Install the CLI

To install the standalone `acp-go-opencode` subprocess an ACP host launches:

```sh
go install github.com/savid/acp-go-opencode/cmd/acp-go-opencode@latest
```

The binary speaks ACP over stdin/stdout and reserves stdout for ACP JSON-RPC;
diagnostics go to stderr. Point it at your native binary with `-path` and at an
ephemeral scratch parent with `-scratch-dir`. See the [CLI reference](/docs/reference/cli) for
every flag.

## Locate the native OpenCode

The adapter launches the `opencode` binary you point it at. Confirm one is
installed and on `PATH` before running:

```sh
opencode --version
```

Integration smoke tests that do not spend model tokens run under
`make test-integration-smoke`.

## Provision Linux identity authority

Linux installations must persist the shared identity-lock root:

```sh
sudo install -d -o root -g root -m 0700 \
  /var/lib/acp-go /var/lib/acp-go/agent-identities
```

Mount that exact local-lock volume into every service or container that can use
the same numeric UID pool, with identical user-namespace UID/GID mappings and
authoritative PID visibility. Otherwise use disjoint pools. Network, FUSE,
pseudo, read-only, and unknown authority filesystems are rejected. Files named
`<uid>.lock` are permanent and must never be unlinked, renamed, or replaced.

Provision a dedicated durable provider state root such as `/var/lib/acp-go-opencode`,
outside and not beneath the authority root. Its ancestors must be root-owned
and not group/world writable; the final directory must be owned by the target
UID:GID with mode `0700`. Keep its device/inode stable.
Set that exact path as both `standaloneStateRoot` in the isolation policy and
the native `-home`; assign a stable nonsecret deployment identity as
`standaloneOwnerId`. The authority's `domain.lock`, `owners.lock`, UID
locks, affinity locks, and owner records are permanent coordination state.
Deleting or reconstructing one beside retained records is corruption, not
routine cleanup.
The adapter does not create, inspect, seed, or remove entries beneath this
target-owned root. OpenCode creates and owns its XDG subdirectories. The
root-owned adjacent `<home>.control` holds adapter locks and must not be created
or modified by the target identity.

---
title: Run Modes
description: Choose between the standalone subprocess and embedding the adapter directly in your Go host.
---

The adapter offers the same behavior through two entry points. Pick by where the
ACP transport lives: use the standalone binary when an editor or host spawns a
subprocess and pipes JSON-RPC over stdio, and embed `Serve` when your host owns
the streams directly.

## Standalone

The command launches OpenCode as its current identity through the ordinary
process implementation. It needs no host-authority setup and makes no managed
process-boundary claim. Managed execution is available only through the
embedded Go API.

`acp-go-opencode` is launched by an ACP client, which drives it over
stdin/stdout. stdout carries ACP JSON-RPC only; diagnostics go to stderr.

```sh
acp-go-opencode -path /usr/bin/opencode -scratch-dir /tmp/acp-opencode
```

Use `-home` when the host assigns an exact exclusive runtime XDG root. Use
`-scratch-dir` as the parent for adapter materialization when no exact home is
assigned. Either location must resolve to an approved local filesystem; remote,
overlay, and unrecognized filesystems are rejected before native startup.

OpenCode npm-installs its plugin loader into every fresh runtime root, which
takes minutes. The adapter caches that install per `opencode` binary in the
[plugin seed cache](/docs/reference/cli#plugin-seed-cache) and copies it into
every new root before launch. The first boot of a new binary fills the cache
through a session-free priming launch, so it pays the install once per binary,
and every runtime root after that, in ordinary and managed execution alike,
starts in seconds. A persistent `-home` reaches the same steady state on its
own after one cold boot.

## Embedded

`Serve` runs the agent against reader/writer streams you supply, so your host
can back the transport with any pipe, socket, or in-memory buffer. `NewAgent`
builds the same agent when you need to hold a reference before serving.

`Serve`:

```go
err := opencodeacp.Serve(ctx, input, output,
	opencodeacp.WithExecutablePath("/usr/bin/opencode"),
	opencodeacp.WithScratchDir(scratchDir),
)
```

`NewAgent`:

```go
agent := opencodeacp.NewAgent(
	opencodeacp.WithExecutablePath("/usr/bin/opencode"),
	opencodeacp.WithScratchDir(scratchDir),
)
```

Both entry points accept the same `Option` values. See the
[Go API reference](/docs/reference/go-api) for the full catalog.

Omitting `WithHostAuthority` selects ordinary same-identity execution. A
managed host passes its authority explicitly:

```go
agent := opencodeacp.NewAgent(
	opencodeacp.WithExecutablePath("/usr/bin/opencode"),
	opencodeacp.WithHome(runtimeRoot),
	opencodeacp.WithHostAuthority(authority),
)
```

The adapter obtains the complete native environment from the authority,
materializes each runtime tree before preparing it, and routes every native
launch through `StartNative`. An unavailable or invalid authority refuses
startup before ordinary execution can be selected. Provider-auth methods are
withheld in this mode because their login brokers are intentionally
ordinary-only.

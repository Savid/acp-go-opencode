---
title: Observability
description: Wire logs, metrics, and traces for the adapter without leaking prompt or tool content.
---

The adapter emits diagnostics two ways: structured logs and OpenTelemetry
signals. Both are opt-in and both redact sensitive content by default.

## Logging

Supply a `*slog.Logger` with `WithLogger` for adapter diagnostics. From the CLI,
`-debug` installs a debug-level text handler on stderr.

<Warning>
stdout is reserved for ACP JSON-RPC. Diagnostics MUST go to stderr; logging to
stdout corrupts the protocol stream. The CLI enforces this, and embedded hosts
should point their logger at stderr or another non-stdout sink.
</Warning>

## OpenTelemetry

Embedded hosts pass providers directly:

- `WithTracerProvider`
- `WithMeterProvider`
- `WithTextMapPropagator`

The command can also configure exporters from standard OpenTelemetry environment
variables when the build includes OTel support.

Telemetry records lifecycle timing, request outcomes, and counters — enough to
observe latency and error rates.

Metrics include ACP request count and duration, prompt count and duration,
cancel count, time to first prompt chunk, token usage, active sessions, and
OpenCode server process starts. Managed-host process inventory and physical
authority metrics belong to the host that implements `HostAuthority`; this
adapter does not infer them from process identifiers or prepared roots.

## What is not recorded

By default telemetry and logs avoid recording prompt text, tool inputs, tool
outputs, and raw OpenCode event bodies, so enabling observability does not leak
conversation content. Raw native event bodies are emitted only through the
explicit [raw events](/docs/features/raw-events) opt-in, never through telemetry.

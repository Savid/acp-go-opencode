---
title: Security
description: The adapter's trust boundaries, native-launch authority, stdout discipline, and credential handling.
---

The adapter's security posture rests on exclusive runtime access, exact
session/turn routing, fail-closed native launch, and keeping credentials out of
anything it persists or streams.

## Native execution boundary

The standalone command and an embedded agent without `WithHostAuthority` use
ordinary same-identity execution. OpenCode receives the adapter's filtered
environment plus configured overlays. On Unix it runs in a separate process
group so ordinary shutdown can terminate the group; this is lifecycle cleanup,
not a managed-host containment claim.

An embedded managed host supplies `WithHostAuthority`. The adapter then:

- obtains the complete base environment from `NativeEnvironment`;
- rejects malformed entries and strips adapter-private and managed-root keys
  before adding its generated XDG, config, database, authentication, and carrier
  values;
- materializes each runtime, carrier, and browser-shim tree before calling
  `PrepareNativeTree`;
- makes no filesystem access beneath a prepared tree until
  `ReclaimNativeTree` succeeds; and
- sends every native executable, including probes and server starts, through
  `StartNative` with the exact environment slice it built.

There is no managed-mode fallback. A nil, panicking, malformed, or failing
authority refuses native work with `ErrHostAuthorityUnavailable`. Failures to
establish terminality or reclaim a tree preserve
`ErrContainmentIncomplete` or `ErrNativeTreeBusy` in the error chain and leave
the affected resources unreused.

`HostAuthority` owns the physical process boundary. `NativeProcess.Wait`
reports only a terminal result, while `Revoke` initiates whole-tree teardown.
The adapter first closes the native protocol and carrier input, then calls
`Revoke`, waits for the terminal result, releases the adjacent runtime control
lock, reclaims prepared trees in reverse order, and finally removes generated
roots. Caller cancellation may detach a waiter but cannot reorder or cancel the
underlying cleanup.

## Runtime and tree ownership

Each Agent owns one shared `opencode serve` generation and one exclusive XDG
root:

- The server binds to `127.0.0.1` and receives a random basic-auth password;
  every REST and SSE request authenticates with it.
- The single-writer claim and liveness lock live under `<xdg-root>.control`,
  outside every tree transferred to host authority.
- Public environment overlays cannot replace `HOME`, XDG roots,
  `OPENCODE_CONFIG`, `OPENCODE_CONFIG_CONTENT`, `OPENCODE_CONFIG_DIR`, or
  `OPENCODE_DB`.
- A shared runtime remains alive when one session cancels or disconnects MCP.
  The session's native work and directory scope settle independently.
- A stream gap, native exit, delivery failure, or unprovable directory cleanup
  retires the exact generation. Retired resources are not reclaimed or removed
  until the shared process is terminal.
- A replacement generation is admitted only after the retired generation's
  cleanup reaches its required boundary. No prepared path is reused while its
  authority lease may still have live processes.

The writable runtime root must have supported local lock semantics. Network,
overlay, and unrecognized filesystems fail before native startup. The control
root is runtime-owned and never transferred to authority.

Provider-auth login brokers are ordinary-only. When `WithHostAuthority` is
supplied, the entire `_opencode/auth/*` capability is absent and every method is
unavailable. The standalone command and ordinary embedded mode retain the
brokered surface when its durable home and ledger root are configured.

## Session and handoff boundaries

Native session IDs, canonical directory scopes, and turn nonces bind every
prompt, abort, permission, question, and event route. A route is exactly scalar
version `1`; malformed, duplicate, fractional, trailing, or unsupported values
are rejected.

Prompt images are read from a local path only when `WithInputHandoffRoot`
configures one, and only from beneath it. The envelope, URI, media type, and
declared size are validated before the filesystem is consulted. The file is
opened relative to the root, must be regular, is read with a strict bound, and
must match the declared digest. The adapter never writes, moves, or deletes
anything under this read root, and no resolved path reaches the native request
or logs. Without the option no inbound path is read.

The read root bounds name resolution, not the bytes a directory entry points
at. A hard link placed beneath it by something already able to write there is
read like any other file. Use a narrow worker-private root and rely on the
digest for byte identity. At most 64 handoff blocks are accepted per prompt.
Every resource blob is decoded and byte-bounded, and text resources count
toward the same per-prompt aggregate.

## stdout is protocol-only

stdout carries ACP JSON-RPC frames exclusively. OpenCode stdout and stderr are
never connected to ACP stdout; adapter diagnostics go to stderr. Anything else
written to stdout corrupts the session.

## Credentials and snapshots

Session snapshots contain only allowlisted native sync events, never XDG files
or the SQLite database. Unknown event kinds or fields fail closed. Before an
atomic store replacement, the adapter scans the complete graph bundle for MCP
headers, MCP environment values, and sensitive process-environment values.

<Warning>
The permission flow is load-bearing for user trust. The adapter never silently
approves a native permission prompt. Keep the session policy at `ask` unless a
trusted host is meant to run unattended.
</Warning>

---
title: Prompt Streaming
description: How OpenCode's native REST and SSE output becomes ACP session updates, and how a turn ends.
---

A prompt turn submits the user message through
`POST /session/{id}/prompt_async` and then consumes the canonical
directory-scoped SSE stream, translating native events into ACP
`session/update` notifications as they arrive. The turn ends when the native
message completes, when the stream fails, when a deadline elapses, or when the
host cancels. Every prompt carries a fresh route-envelope turn nonce; an active
cancel must carry that same nonce.

## Stream mapping

Native part events map onto ACP update variants:

| Native part | ACP update |
|---|---|
| Text | `agent_message_chunk` |
| Reasoning | `agent_thought_chunk` |
| Tool call | `tool_call` / `tool_call_update` |
| Todos | `plan` |
| Token totals | `usage_update` |

ACP text blocks and text embedded resources become native text parts. A blob
embedded resource whose MIME type is `image/*`, and a direct ACP image block,
become a native file part carrying the embedded base64 data as a data URL. When
an image block carries both `data` and a `uri`, the embedded `data` is
authoritative for the submitted pixels and the URI contributes only filename
provenance; the adapter never fetches it.

## Prompt media validation

Prompt media is validated before the turn starts, deterministically at the first
failing block, and indexes are assigned across media-bearing blocks in request
order. The image input allowlist is exactly `image/png`, `image/jpeg`,
`image/gif`, and `image/webp`, static frames only: a multi-descriptor GIF, a
WebP `VP8X` `ANIM` flag, and a PNG `acTL` chunk (APNG) are rejected without
decoding any raster. A declared MIME is normalized — lowercased, trimmed, and
stripped of parameters — before it is tested for the `image/` prefix, so a
case or parameter variant is routed to the image contract and then rejected on
the allowlist rather than escaping it. The allowlist itself compares the
declared type exactly, so `IMAGE/PNG` is `invalid_media_type`.

Missing data, undecodable base64, a MIME outside the allowlist, a
sniffed/declared MIME mismatch, unreadable dimensions, and decoded bytes over
the configured `ImageLimits` each fail with JSON-RPC `-32602` and a
`prompt.image` error taxonomy (`error`, `index`, and byte sizes). When the
selected model's authenticated provider metadata (`capabilities.input.image`)
says the model cannot accept images, the prompt is rejected as
`unsupported_by_model`; absent metadata forwards the turn and lets the provider
decide.

A blob embedded resource is gated whatever its MIME. Its base64 must decode, its
decoded bytes must fit the per-image bound, and they count toward the per-prompt
total, so no resource channel carries unbounded or unvalidated bytes to the
harness. A blob outside the image contract is verdicted under `prompt.resource`
with the same `error` values, and its native representation is otherwise
unchanged.

## Handoff input form

When the host sets `WithInputHandoffRoot`, an image block may carry its bytes by
reference instead of inline: empty `data`, a `file://` URI beneath the
configured read root, and a
`_meta["acp-go.dev/handoff"]` object containing exactly `version: 1`, a
64-character lowercase-hexadecimal `digest`, and an integer `sizeBytes`.

Form selection runs ahead of every embedded gate. Non-empty `data` is always the
embedded form, even alongside a handoff envelope. Empty `data` with a handoff
envelope or a `file://` URI is the handoff form. Empty `data` with neither stays
`missing_data`.

A handoff block resolves in a fixed order, first failure winning:

| `error` | Cause |
|---|---|
| `invalid_handoff` | The block is malformed as a block: no configured read root, an absent or undecodable envelope, an unsupported `version`, an unrecognized envelope field, a malformed `digest` or `sizeBytes`, or a URI that is not an absolute local `file://` path. |
| `path_not_allowed` | The path resolves outside the read root, escapes it through a symlink, or is not a regular file. |
| `missing_file` | A path inside the read root that does not exist or cannot be opened or read. |
| `handoff_digest_mismatch` | The bytes do not match the declared `sizeBytes` and `digest`. |

Resolution is bounded and symlink-safe: containment is checked on the cleaned
path, symlinks are resolved, containment is checked again on the resolved path,
and only then is the file mode inspected. The read is bounded at the per-image
byte gate plus one byte. Verification is fail-closed — a mismatch is a rejection
and never a fall back to the embedded form — and a file that overran the bound
cannot be verified, so the byte gate rejects it `too_large` on its real on-disk
size. All four verdicts are JSON-RPC `-32602`, are fatal before the turn starts,
and carry a `message` naming the real cause without repeating the host path.

Bytes that pass then run the same gate chain as the embedded form, minus the two
gates that need base64, and count toward the per-prompt total identically. The
validated bytes reach OpenCode as the same data URL an embedded block builds, so
a handoff turn and an embedded turn over the same bytes produce byte-identical
native requests. The handoff path itself never appears in the native request:
nothing derives a filename from it, and it does not outlive the validation read.

Native tool results and assistant file parts that carry an image are mapped back
to ACP as embedded image content (each agent image alone in its own
`agent_message_chunk`, tool images as the tool call's complete content array).
Tool-result images are the common path; an assistant file part is the defensive,
rarely exercised case, since model-native image output does not survive as a
standalone assistant file part in practice. A
remote URI-only artifact becomes an ACP `resource_link` on its true provenance;
the adapter never downloads it. Output MIME is the truthful sniffed type and is
not allowlisted. Emitted bytes over the configured or transport-frame limit fail
the turn with a `stage: "image_output"` envelope rather than reaching the wire.

OpenCode text and reasoning part events carry the complete part plus, on live
updates, an explicit appended `delta`. The adapter forwards that delta and
reconciles the final REST response against what was already delivered, so a
metadata-only part change never repeats text. A final non-append rewrite cannot
be represented by ACP chunk updates; it is diagnosed without logging content
and is not appended as corrupt duplicate text.

Each native tool part produces exactly one `tool_call`. Later pending,
in-progress, completed, or failed states for the same call produce
`tool_call_update`; failed states preserve the native error in `rawOutput`.
If the first observed state is already terminal, the initial `tool_call`
carries that terminal status and no follow-up update is fabricated.
Identical message-level and step-level token snapshots produce one
`usage_update`, while a changed snapshot still produces a later update.

The native stream also echoes the just-posted user message back as part events.
During a live turn those are suppressed — the client already owns that content,
so only agent output streams back. The suppression is turn-local: user messages
still replay as `user_message_chunk` during `session/load`.

## How a turn ends

A turn resolves to exactly one outcome, and cancellation always wins a tie with
any concurrent failure:

- **Success** — the native message completes; the prompt returns its stop
  reason and usage.
- **Cancelled** — the host cancelled, or a coinciding deadline resolves as
  cancelled rather than timeout; the prompt returns `cancelled`.
- **Failure** — the turn returns one terminal ACP internal error carrying a
  uniform `opencode_turn_failed` payload. Transport/provider failures leave the
  session usable.

The failure payload's `cause` names the failure class:

| `cause` | Meaning |
|---|---|
| `provider` | The model or provider raised an assistant error; carries the native `message`, plus `statusCode`/`providerCode` when reported. |
| `transport` | The SSE stream or REST call failed, or the shared `opencode serve` runtime exited; carries the real detail, never a bare `EOF`. |
| `timeout` | The turn exceeded the deadline set by `WithTurnTimeout`. |

By default there is no deadline. `WithTurnTimeout` bounds a single turn; when it
elapses the adapter sends native abort as a best-effort hint, retires that
turn's exact shared-runtime generation, and waits for the one memoized
containment result before reopening turn admission. Native `idle` status is
never accepted as process containment. Failure to complete the selected
boundary poisons the affected session and quarantines the runtime resources.
Darwin best-effort completes only the captured original process group plus
direct-child reap and never claims escaped descendants are absent.
The same fence is used for host cancellation and stream/control failures that
can leave native work running. See
[Models and config](/docs/features/models-config) for the
provider-error and structured-output details, and
[Metadata](/docs/reference/meta) for the full error payload.

Because cancellation containment retires a shared runtime, an Agent admits at
most one native prompt turn at a time across all of its logical sessions.
Queued prompts remain context-cancellable. Lifecycle calls and bounded REST
calls retain their separate concurrency limit.

A shared-runtime exit fails the in-flight turn with this same
`opencode_turn_failed` transport shape; an overlapping cancel still resolves
as cancelled, while containment failure is never erased by the runtime-loss
race. Logical sessions remain loaded. A later prompt starts a replacement
runtime and restores the last committed event generation before routing any
user content.

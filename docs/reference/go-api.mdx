The complete signatures and doc comments live on
[pkg.go.dev](https://pkg.go.dev/github.com/savid/acp-go-opencode). This page
indexes the surface and explains the contracts that matter to an embedding host.

## Entry points

```go
agent := opencodeacp.NewAgent(opts...)
err := opencodeacp.Serve(ctx, input, output, opts...)
```

`Serve` runs against the supplied streams and closes the agent before it
returns. `NewAgent` builds the same agent when the caller needs a reference.
Both accept the same `Option` values.

Shutdown errors preserve public sentinels. `ErrHostAuthorityUnavailable` means
the supplied authority cannot accept more managed work.
`ErrContainmentIncomplete` means terminal process-tree proof or cleanup did not
complete. `ErrNativeTreeBusy` means reclaim found live lease processes. A host
must keep affected resources out of reuse.

## Host authority

Omitting `WithHostAuthority` selects ordinary same-identity execution. A
managed host implements this exact boundary:

```go
type HostAuthority interface {
	NativeEnvironment() map[string]string
	PrepareNativeTree(context.Context, string) error
	ReadNativeAppendLog(context.Context, string, uint64) ([][]byte, error)
	ReclaimNativeTree(context.Context, string) error
	StartNative(context.Context, NativeRequest) (NativeProcess, error)
}

type NativeProcess interface {
	Stdin() io.WriteCloser
	Stdout() io.ReadCloser
	Stderr() io.ReadCloser
	Wait(context.Context) (NativeResult, error)
	Revoke(context.Context) error
}
```

`NativeRequest` contains `Executable`, `Arguments`, `Environment`, and
`WorkingDirectory`. `NativeResult` contains `ExitCode`, `Signal`, and
`Revoked`.

The environment map must be complete and valid. The adapter filters reserved
keys, applies `WithEnv`, adds its managed runtime values, sorts the resulting
environment, and passes that exact slice to `StartNative`. It does not mix in
the adapter's ambient environment.

Every prepared tree is fully materialized before `PrepareNativeTree`. From a
successful prepare until a successful reclaim, the adapter performs no
filesystem access beneath that tree. The runtime lock remains at
`<xdg-root>.control`, outside the prepared root. Teardown closes protocol input,
calls `Revoke`, reaches terminal `Wait`, releases the lock, reclaims prepared
trees in reverse order, and then removes generated roots. A failed prepare is
opaque and leaves host cleanup in force; a busy reclaim retains retry ownership
and blocks replacement admission. Cancelling a `Wait` caller only detaches that
caller, and a later wait still receives the single terminal result. An
authority error is never retried through ordinary execution.

## Agent options

| Option | Purpose |
|---|---|
| `WithExecutablePath` | Path to the `opencode` binary. |
| `WithHostAuthority` | Route all managed native environment, tree, start, wait, and revoke work through the supplied authority. |
| `WithScratchDir` | Parent for a generated shared runtime root and transient adapter material; empty uses the system temp directory. |
| `WithHome` | Exact exclusive shared OpenCode XDG root owned by this Agent. |
| `WithDefaultModel` | Default `provider/model` for new sessions. |
| `WithEnv` | Agent-wide ordinary-variable overlays. Managed OpenCode/XDG roots remain adapter-owned. |
| `WithSeedFiles` | Immutable files materialized in the shared config root before launch. |
| `WithPluginSeedDir` | Cache of the OpenCode plugin install copied into new runtime roots; empty uses `plugin-seed` under the user cache directory. |
| `WithPluginSeed` | Enable or disable the plugin install cache; enabled by default. |
| `WithSessionStore` | Host-provided persistence backend. |
| `WithSessionStoreLoadTimeout` | Bound each store read during hydration; default `10s`. |
| `WithConcurrencyLimits` | Cap concurrent client calls and active sessions. |
| `WithTurnTimeout` | Per-turn deadline; `0` disables it. |
| `WithImageLimits` | Decoded-byte bounds for prompt and emitted images. |
| `WithInputHandoffRoot` | Absolute read root for digest-verified local image handoff. |
| `WithProviderAuthRoot` | Durable values-free provider-auth ledger root for ordinary execution. |
| `WithProviderAuthDirectHome` | Declared for host configuration symmetry; OpenCode rejects a configured value as unsupported. |
| `WithAgentName` / `WithAgentTitle` / `WithAgentVersion` | Identity in the initialize response. |
| `WithLogger` | `*slog.Logger` for adapter diagnostics. |
| `WithTracerProvider` / `WithMeterProvider` / `WithTextMapPropagator` | OpenTelemetry wiring. |

Provider auth is advertised only when `WithProviderAuthRoot` and `WithHome` are
both configured in ordinary mode. Supplying `WithHostAuthority` withholds the
entire provider-auth surface, regardless of those options.

`ImageLimits` has four decoded-byte fields. Input fields bound each image and
the prompt aggregate; output fields bound each emitted image and tool-call
aggregate. Every field defaults to 6 MiB, and `0` disables that policy limit.
Transport-frame limits still clamp output. Input supports static PNG, JPEG,
GIF, and WebP. Effective input bounds are advertised during initialize.

`WithInputHandoffRoot` enables digest-verified `file://` image input beneath an
absolute read root. The adapter never writes, moves, or deletes beneath it.
Leaving it unset rejects the handoff form.

`WithSeedFiles` maps relative config paths to bytes materialized before server
start. A seeded `opencode.json` is merged with the adapter's `$schema` and must
not contain `permission` or `mcp`, which remain session and directory scoped.
Absolute paths, parent escapes, and empty keys are rejected.

`WithPluginSeedDir` names the cache of the npm tree OpenCode installs for its
plugin loader. The adapter copies a cached tree into each new runtime root
before launch so OpenCode skips the install. When the cache has no entry for
the running binary, a priming launch fills it first: a throwaway runtime under
the scratch parent that performs the install, serves no session, and is torn
down and harvested before the runtime itself starts. Under `WithHostAuthority`
the priming launch is prepared, started, and reclaimed through the same
authority, and its tree is read only after reclaim. See the
[CLI reference](/docs/reference/cli#plugin-seed-cache) for the layout and
[Security](/docs/operations/security) for the trust boundary.

## Session request builders

Client-side helpers populate the adapter's `_meta.opencode` vocabulary:

| Builder | Builds |
|---|---|
| `NewSessionRequest` | `session/new`. |
| `LoadSessionRequest` / `ResumeSessionRequest` | `session/load` / `session/resume`. |
| `ForkSessionRequest` / `CallForkSession` | `_opencode/session/fork`. |
| `ListSessionsRequest` with its list options | `session/list`. |
| `NewTurnNonce` | A cryptographically random turn identity. |
| `PromptRequest` / `TextPromptRequest` | `session/prompt` with a required turn nonce. |
| `CancelRequest` | `session/cancel` for the active turn nonce. |
| `SetConfigOptionRequest` / `SetModelRequest` | `session/set_config_option`. |
| `StdioMCPServer` / `HTTPMCPServer` | MCP server definitions. |

Prompt and cancel builders stamp a route only for a non-empty turn nonce of at
most 4096 bytes. Reserved `acp-go.dev/*` metadata keys cannot be supplied by
`WithSessionMeta` or `WithListSessionsMeta`.

Session options include `WithSessionMCPServers`,
`WithSessionAdditionalDirectories`, `WithSessionMeta`,
`WithSessionOutputSchema`, `WithSessionRawEvents`, and
`WithSessionOpenCodeOptions`.

`OpenCodeOptions` is built with `NewOpenCodeOptions` plus model, output-schema,
mode, permission, environment, and extra-path options. Session environment and
extra path directories are scoped to the addressed native session rather than
the shared server. `PATH` and managed runtime roots are refused in session
environment. Ordered extra paths persist across load, resume, recovery, and
fork; environment is supplied again on reload instead of storing bearer values.

`ErrRuntimeLockUnsupported` means the platform cannot provide the runtime
home's advisory single-writer fence. Construction fails rather than continuing
unlocked.

## Session store

`SessionStore` is the persistence interface and `NewInMemorySessionStore` is
the default implementation. Rows use `SessionStoreFormat`
(`opencode-sync-events-v1`). See [Session store](/docs/features/session-store).

`InspectSessionStoreTerminalState` validates the committed entries for a
logical ACP session and returns the latest durable terminal assistant message
identity for host checkpoint reconciliation.

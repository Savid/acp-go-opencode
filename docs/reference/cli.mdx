```sh
acp-go-opencode [flags]
```

The binary speaks ACP over stdin/stdout; stdout carries JSON-RPC only and
diagnostics go to stderr. It uses Go `flag` single-dash syntax.

## Required standalone isolation policy

Normal serve mode is Linux-only and requires
`-process-isolation-config=/absolute/path/process-isolation.json`.
`-version` and the Darwin containment diagnostic subcommands are exempt.
The policy must be a root-owned, single-link regular file with mode `0600`.
Every component is opened from `/` without following symlinks, and every
ancestor must be root-owned and not writable by group or other. Unknown JSON
fields and trailing JSON values are rejected.

```json
{
  "uid": 20001,
  "gid": 20001,
  "standaloneOwnerId": "opencode-deployment-1",
  "standaloneStateRoot": "/var/lib/acp-go-opencode",
  "baseEnvironment": {
    "PATH": "/usr/local/bin:/usr/bin:/bin",
    "HOME": "/var/lib/acp-go-opencode",
    "USER": "acp-go-opencode",
    "LOGNAME": "acp-go-opencode",
    "LANG": "C.UTF-8"
  },
  "inheritEnvironment": []
}
```

`standaloneOwnerId` is the nonsecret, case-sensitive deployment identity:
1--256 ASCII bytes, beginning alphanumeric, with remaining bytes limited to
alphanumerics and `._:@/-`. `standaloneStateRoot` is the existing dedicated
durable provider state root, is neither `/` nor equal to or beneath
`/var/lib/acp-go/agent-identities`, and must equal the configured native home. Its clean
absolute UTF-8 path is limited to 4096 bytes with no control character, and
Linux resolves the complete path componentwise from `/` without following
symlinks or magic links. Every ancestor is root-owned and not group/world
writable; the final directory is owned by the configured UID:GID with mode
`0700`. It binds the exact path, device, and inode.

The supervisor must run as root. The UID/GID must name a nonroot account with
that same-name private primary group, no supplementary groups, and a target-owned mode
`0700` home matching `HOME`, reached without symlinks beneath protected
root-owned ancestry; `/root` and `/nonexistent` are forbidden. `USER` and
`LOGNAME` must match the account.
`PATH` must contain existing canonical absolute directories. The child gets
only `baseEnvironment` plus variables explicitly named in
`inheritEnvironment`; identity, search-path, loader, interpreter, XDG/native
home, and adapter-private variables cannot be inherited. Unset or duplicate
inheritance entries fail startup. Darwin, Windows, and other platforms refuse
standalone native mode rather than weakening this contract.

Provision the target as a locked system account with a non-login shell, its
same-name private group, and no sudo policy. Its UID and primary GID cannot be
shared by another account. Password locking is not a substitute for disabling
login paths, and a locked account still needs the validated private writable
home for native tools.

## Flags

| Flag | Meaning | Default |
|---|---|---|
| `-path` | Path to the `opencode` CLI. | resolved from `PATH` |
| `-process-isolation-config` | Required absolute path to the standalone Linux isolation policy described above. | — |
| `-scratch-dir` | Parent for the shared runtime root and transient adapter scratch. | system temp directory |
| `-home` | Exact exclusive shared OpenCode XDG root; defaults to and, when set, must equal `standaloneStateRoot`. | policy value |
| `-provider-auth-root` | Durable host-owned root holding the provider-auth ledger. Empty leaves the provider-auth surface unadvertised. | — |
| `-provider-auth-direct-home` | Canonical native home an account-level provider-auth leg may read or clear. Rejected by this adapter at session start. | — |
| `-model` | Default model as `provider/model`. | — |
| `-debug` | Write debug logs to stderr. | off |
| `-version` | Print the adapter version and exit. | — |
| `-opencode-pure` | Start OpenCode without external plugins. | off |
| `-opencode-question-tool` | Enable native question-tool elicitation mapping. | off |
| `-opencode-log-level` | Native OpenCode server log level. | native default |
| `-opencode-health-timeout` | OpenCode server readiness timeout. | `60s` |
| `-seed-file <relpath>=<hostpath>` | Seed a file into the shared runtime config root (repeatable). | — |

The standalone command never launches native work on Darwin. The operational
subcommands below remain available to inspect generations left by an embedded
host using `WithDarwinBestEffortContainment`.

Operators can inspect retained records without signalling processes:

```sh
acp-go-opencode containment diagnose -scratch-dir /path/to/scratch
```

Cleanup is deliberately explicit and revalidates every marker-correlated PID:

```sh
acp-go-opencode containment cleanup \
  -scratch-dir /path/to/scratch \
  -runtime-id 0123456789abcdef0123456789abcdef \
  -force
```

PID-by-PID cleanup has an unavoidable PID-reuse time-of-check/time-of-use race:
the PID can be reassigned after revalidation and an unrelated process can be
signalled. Marker correlation is not ownership. Markers can be scrubbed, so
cleanup can leave escaped processes behind; ambiguous identities are reported
and are not signalled. The fixed five-second cleanup deadline starts before the
first process enumeration.

## Seeding files

`-seed-file` reads the host file at `<hostpath>` and seeds its contents at the
relative path `<relpath>` inside the shared OpenCode config root
(`<XDG_CONFIG_HOME>/opencode/`) before the server starts. Repeat the flag to
seed several files. The seeded `opencode.json` is deep-merged with the wrapper's
managed `$schema`. A seeded `opencode.json` containing `permission` or `mcp` is
rejected because those values are applied at native-session and directory
scope. Every other seeded file is written verbatim. Absolute paths, `..`
escapes, and empty keys are rejected.

[Models and config](/docs/features/models-config).

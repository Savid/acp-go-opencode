```sh
acp-go-opencode [flags]
```

The binary speaks ACP over stdin/stdout; stdout carries JSON-RPC only and
diagnostics go to stderr. It uses Go `flag` single-dash syntax.

## Execution mode

The command uses ordinary same-identity execution on every supported platform.
It exposes no flag for managed host authority. Applications that require a
host-owned native process boundary embed the Go package and pass
`WithHostAuthority`.

## Flags

| Flag | Meaning | Default |
|---|---|---|
| `-path` | Path to the `opencode` CLI. | resolved from `PATH` |
| `-scratch-dir` | Parent for the shared runtime root and transient adapter scratch. | system temp directory |
| `-home` | Exact exclusive shared OpenCode XDG root. | generated root |
| `-provider-auth-root` | Durable host-owned root holding the provider-auth ledger. Empty leaves the provider-auth surface unadvertised. | — |
| `-provider-auth-direct-home` | Canonical native home an account-level provider-auth leg may read or clear. Rejected by this adapter at session start. | — |
| `-model` | Default model as `provider/model`. | — |
| `-debug` | Write debug logs to stderr. | off |
| `-version` | Print the adapter version and exit. | — |
| `-opencode-pure` | Start OpenCode without external plugins. | off |
| `-opencode-question-tool` | Enable native question-tool elicitation mapping. | off |
| `-opencode-log-level` | Native OpenCode server log level. | native default |
| `-opencode-health-timeout` | OpenCode server readiness timeout. | `60s` |
| `-seed-file <relpath>=<hostpath>` | Seed a file into the shared runtime config root (repeatable). | — |
| `-plugin-seed-dir` | Cache of the OpenCode plugin install copied into new runtime roots. | `plugin-seed` under the user cache directory |
| `-no-plugin-seed` | Disable the plugin install cache. | off |

## Plugin seed cache

OpenCode installs its plugin loader, the `@opencode-ai/plugin` npm package,
into `<XDG_CONFIG_HOME>/opencode/` the first time a runtime root names any
plugin. This adapter always names one, its session carrier, and without `-home`
every launch gets a fresh root, so a cold boot waits minutes for that install.

The adapter therefore keeps one copy of the tree OpenCode produced, keyed by the
identity of the `opencode` binary, in the plugin seed cache and copies it into
each new runtime root before launch. OpenCode finds the install complete and
skips it, so a warm boot answers `session/new` in seconds. Stale entries are
removed after thirty days and the cache keeps a handful of binaries at most.

When the cache holds no entry for the running binary, the adapter fills it
before the runtime starts through a priming launch: a throwaway runtime root
under `-scratch-dir`, named `acp-go-opencode-plugin-prime-*`, that boots the
same binary with the same environment and seed files, performs the install,
and is shut down as soon as the session carrier handshake proves it complete.
The tree it leaves is harvested into the cache and the root is removed, and the
runtime then restores from the fresh entry. No session ever reaches the priming
runtime, which is what makes its tree safe to copy into every later root. The
priming launch has its own readiness budget of ten minutes, so the first boot
of a new binary no longer needs a raised `-opencode-health-timeout`; a binary
upgrade changes the key and primes again on the next boot. Under a host
authority the priming root is prepared, started, and reclaimed through the same
authority, and is read only after reclaim.

The default location is `acp-go-opencode/plugin-seed` beneath the user cache
directory: `$XDG_CACHE_HOME` or `~/.cache` on Linux, `~/Library/Caches` on
macOS, and `%LocalAppData%` on Windows. `-plugin-seed-dir` relocates it and
`-no-plugin-seed` turns it off. `-opencode-pure` runs install no plugin loader
and never touch the cache. The cache holds code OpenCode executes; see
[Security](/docs/operations/security) for who may write it.

## Seeding files

`-seed-file` reads the host file at `<hostpath>` and seeds its contents at the
relative path `<relpath>` inside the shared OpenCode config root
(`<XDG_CONFIG_HOME>/opencode/`) before the server starts. Repeat the flag to
seed several files. The seeded `opencode.json` is deep-merged with the wrapper's
managed `$schema`. A seeded `opencode.json` containing `permission` or `mcp` is
rejected because those values are applied at native-session and directory
scope. Every other seeded file is written verbatim. Absolute paths, `..`
escapes, and empty keys are rejected.

For a worked example see
[Models and config](/docs/features/models-config).
